# Next.js 工作台

规划还包含检索引用、选题建议和人工确认创建任务。这些还没有做。核心业务由 Python API 提供，页面不重复实现解析和入库。

当前包含登录页 `/login`、素材入库页 `/`、列表 `/library` 与详情 `/library/{id}`。浏览器请求本站 `/backend`，Next.js 转发到 Python API。默认地址是 `http://127.0.0.1:8000`，可用服务端环境变量 `API_URL` 改目标。先按 [后端登录配置](../api/README.md#个人登录配置) 配置 GitHub OAuth；页面门禁与后端接口均验证身份。

在仓库根目录开两个终端：

```bash
npm run dev:api
npm run dev:web
```

然后打开 http://localhost:3000 。登录后一次上传一篇。同一来源和同一 slug、相同内容显示已在库中；内容不同则自动覆盖文章和全部分块，文章 ID 保持不变。列表支持分页，详情展示正文、元数据及按顺序排列的分块。正文按纯文本显示，避免执行素材中的 HTML。

依赖安装在 `apps/web`，版本见该目录的 `package.json`。尚未部署。

生产构建命令：`npm run build --prefix apps/web`（仓库根目录执行）。部署时 API_URL 需要指向已上线的 Python 后端，默认的 127.0.0.1 仅适用于本地开发。

验收边界：新增页面生产构建通过；后端有会话、OAuth 模拟和真实数据库事务测试。浏览器工具当前不可用，真实 GitHub 登录以及登录后的上传／覆盖／查看尚未完成端到端验收。旧版上传页浏览器记录不能替代本次验收。未部署。
