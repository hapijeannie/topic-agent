# L／S 岗位要求与项目映射

来源：用户于 2026-11-16 在本项目对话提供的岗位全文。以下保留关键要求并结构化摘录；不是联网招聘信息，不推测公司身份。个人项目成果不能替代或虚构实际工作年限。

## L 岗位

核心目标：负责产品业务链路研发与交付，打通企业数据与知识接入、智能问答、本体语义查询、Agent 发布及效果评测，保障可靠性、权限隔离和可观测性，具备自主推进与模块负责能力。

职责：

- 知识库与 RAG：覆盖知识收集、加工、审核、更新、沉淀；优化解析切片、召回、引用溯源、知识隔离及问答效果。
- Agent 场景：硬件问答、HowTo、文本 Chat、语音 Voice；意图路由、知识检索、工具调用、问答输出；优化稳定性、时延与解决率。
- 工程交付：知识产品与观测评估平台方案；接口、权限、并发、多租户隔离、部署、排障、性能优化，服务海外售后。
- 指标协同：与产品、算法、知识运营、海外业务协作，围绕 AI 解决率、检索精准度、自服转化率和问题闭环率迭代，沉淀组件。

资格与能力：

- 本科及以上，３年以上后端或全栈经验，其中至少１年实际参与 RAG、Agent 或企业级 AI 问答设计与落地；知识库、客服、企业搜索、ToB 经验优先，海外／国际化加分。
- 能独立设计文档解析、切片策略、Embedding 选型、向量检索、混合检索与 Rerank；熟悉元数据过滤、Query 改写、多路召回、引用溯源、增量更新、知识隔离；通过召回率、忠实度、时延等指标优化，不能只是调用框架。
- Agent／工作流实际落地：工具调用、规划执行、多步拆解、状态与记忆、人机协同；失败重试、降级、工具权限、上下文压缩与效果评估，优化稳定性、成本和时延。
- 必须具备全栈能力，使用 LangChain／LangGraph 或同类自研方案；熟悉向量库、PostgreSQL、Redis 配合使用。必须有 Codex／Claude Code 等 AI 编程提效经验，并能将生成代码纳入可维护规范。
- 架构与运维：从业务拆解知识库、检索、编排、接口；容器化、配置与环境隔离、日志监控、限流熔断、效果与成本观测。
- 权限与并发：RBAC、数据权限、多租户／知识空间隔离、异步任务、缓存、队列、高并发下的稳定性与一致性。
- 跨团队沟通、英文读写及海外业务对接、逻辑与抗压能力、并行迭代；团队期待理解业务和 AI 产品逻辑，主动发现痛点并推动上线。

语言边界：原文没有明确指定必须使用 Python，核心是全栈和 AI 工程交付。

## S 岗位

职责：

- 需求分析，将业务目标抽象为 Agent 任务、工作流、工具链与可验收产品能力。
- 端到端 Agent：规划执行、状态与记忆管理、多 Agent 协作、异常兜底。
- 集成 Skill、MCP、Tool、知识库、企业系统和 AI4S 模型，优化 Prompt、工作流与交互。
- 建立场景评测集与线上监控，优化任务成功率、准确性、稳定性、时延、成本。
- 服务化、部署、调试、生产问题定位，保障真实业务可用。
- 与产品、组件、平台、FDE 团队协作，完成 PoC 与生产落地，沉淀行业方案和工作流模板。

资格：

- 本科及以上，计算机、AI、软件工程等相关专业。
- **熟练掌握 Python，并熟悉 Golang 或 TypeScript 中至少一种**，具备后端开发与系统集成能力。
- 熟悉 LLM 应用与 Agent 架构，理解 Prompt Engineering、RAG、Tool Use、记忆与多 Agent。
- 熟悉 LangGraph、LangChain、LlamaIndex、AutoGen 至少一种框架，有真实业务 Agent 开发经验。
- 具备 API、数据库、消息队列、Docker、基本云原生能力，能独立调试和定位生产问题。
- 具备业务理解、需求抽象、跨团队协作能力，推动原型走向生产。

加分项：行业智能化、AI4S、HPC、科研计算等 Agent 生产落地经验。本项目不因加分项扩展到科研计算领域。

## 本项目取舍

- 最终形态为 Next.js 工作台＋Python FastAPI 后端＋PostgreSQL／pgvector。Next.js 能实现后端；采用 Python 的主要依据是 S 的明确语言要求与 AI 后端学习目标。
- Next.js 负责交互，Python 负责核心业务，避免两套后端重复业务规则。LangGraph 在 Agent 人工确认与状态管理阶段接入，不用于包装普通文件导入。
- 先打通上传入库、带引用的 RAG、选题建议与确认创建任务三条链路。第一条链路就包含最小上传页面，CLI 继续作为调试入口。
- RAG 初版即建立小型固定评测集，覆盖命中、引用支持、空结果与耗时；基线后再对照混合检索与 Rerank。
- 最小闭环后补长期记忆、多 Agent、MCP、Skill、复杂权限、增量更新、队列缓存和并发优化，不删除长期学习目标。
- 第一版可使用 Vercel 部署前端与 FastAPI，PostgreSQL 为独立持久化服务。标准 FastAPI 保留容器部署路径；Docker 单独实践验收，不能以 Vercel 部署代替岗位 Docker 能力。
- 以真实运行记录、评测对比、失败处理和个人实际使用证明能力，不宣称满足岗位年限或已有企业客户经验。
